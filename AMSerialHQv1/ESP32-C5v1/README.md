# AMSerialHQv1 for ESP32-C5

The C5 port transmits mono AM on fixed **2.4 GHz** and **5 GHz** profiles. Use the HTML in this folder for its RF band selector and per-band ASK mapping.

## Build and play

1. Open [AMSerialHQv1_C5.ino](AMSerialHQv1_C5/AMSerialHQv1_C5.ino) with **Arduino ESP32 3.3.12**. Select **ESP32C5 Dev Module**, **240 MHz**, **DIO 80 MHz**, PSRAM disabled, and **USB CDC On Boot disabled** for the USB-to-UART bridge. Set the flash size and partition scheme for your module. The documented bench used an **8 MB** flash layout.
2. Upload the sketch, close Serial Monitor, then open [AM_LIVE_WEBSERIAL_HIFI.html](AM_LIVE_WEBSERIAL_HIFI.html) in desktop Chrome or Edge from the [local Web Serial server](../../README.md).
3. Connect the serial bridge, select the RF band, and pre-encode an audio clip. If you change the band, pre-encode the clip again so the player applies the other band's envelope mapping. Select AM on your SDR and tune near the programme carrier.

| RF profile | Nominal AM carrier | Nominal CW marker |
| --- | ---: | ---: |
| 2.4 GHz, channel 7 | 2442.312500 MHz | 2442.625000 MHz |
| 5 GHz, channel 36 | 5180.312500 MHz | 5180.625000 MHz |

The firmware boots with RF off and the 2.4 GHz profile selected. Changing bands turns RF off. Each transmission begins with one second of CW, and the firmware turns RF off at the end of the clip unless you enabled continuous CW manually. **ARRÊT RF** turns the carrier off. See the [repository RF test notes](../../README.md).

## Transport and bench check

The port uses **2,000,000 baud, 8N1** and keeps the `0xA7` Q8.8 ASK stream format at **32, 48, or 64 kSa/s**. The idle command `0xA8` followed by `0x00` or `0x01` selects the 2.4 or 5 GHz profile. APWR adjusts base attenuation. The control value is unitless.

The matching firmware and player were tested with a 1 kHz tone at all three rates. With APWR 63 and a 60% depth setting, HackRF received **60.48–60.63%** modulation in the initial 2.4 GHz test and **59.97–60.07%** at 5 GHz. The two sidebands appeared about 1 kHz from the actual carrier. The bench streamed data generated by the HTML encoder through a serial test driver.
